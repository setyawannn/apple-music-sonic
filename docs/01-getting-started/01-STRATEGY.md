# Apple Music RS — Strategy

> Last updated: 2026-11-13
> Status: streaming MVP works; transport and library surfacing are the remaining work.

---

## What this project is

A personal, single-user Windows client that reproduces the Apple Music desktop experience
in Rust + Tauri, on top of the user's **existing subscription**.

**The MVP is one sentence: sign in, browse my Apple Music, play full songs properly.**

Not a music manager. Not an offline downloader. Not a local-file player. Those were
earlier ambitions; local-file playback is now parked
(`docs/03-implementation/04-PARKED-LOCAL-PLAYBACK.md`).

## Constraints

## How the core problem was solved

Apple encrypts streaming audio with FairPlay. Two routes were considered:

**Route A — implement decryption natively (abandoned).**
Load Apple's own DLLs (`CoreFP.dll`, `CoreMedia.dll`, `CoreAudioToolbox.dll`) via FFI and
call their decryptors in-process. `src-tauri/src/drm/**` is the result: DLL staging
works, ordinals resolve, unit tests exist. It never produced audio, because the license
`challenge` can only be generated by a real CDM — Apple's key server rejects a challenge
fabricated outside one.

**Route B — host Apple's own player (shipped).**
A hidden WebView2 loads `music.apple.com`, signs in with the user's existing profile, and
drives **MusicKit** through injected JavaScript. Windows' built-in **PlayReady CDM** — which
ships with WebView2 — handles FairPlay and decryption. We never touch ciphertext.

Route B is why the app works today. The trade-off is honest: the hidden browser is heavier
than a native decoder, and the ceiling is **AAC 256 kbps** (WebView2 exposes no ALAC
decoder, and EME output cannot be read as PCM). Lossless is out of reach on this path.

```diff
- "Reverse engineer FairPlay"            (impossible, and not attempted)
- "Reimplement the CDM in Rust"          (impossible — challenge needs a real CDM)
+ "Host Apple's player, borrow its CDM"   (shipped)
```

## The plan

**P0 — Make playback truthful.**
Stop waiting on a readiness signal that can never arrive; give the player a state channel
that CSP cannot block; wire seek into the progress bar. Until this lands, the UI is guessing.

**P1 — Real transport.**
Drive MusicKit's own queue: next, previous, shuffle, repeat, stop. Today those buttons call
the parked local engine and do nothing while streaming.

**P2 — Surface the Apple library.**
"Library" tab reads the iCloud library, "Playlists" reads cloud playlists, album cards open
an album detail view. The welcome screen stops offering to scan a folder.

**P3 — Polish.**
Loading state while a song buffers, clear error when a track is unavailable, resume last
song on launch, keyboard and media keys.

**P4 — Revisit parked work.**
Decide: develop local file playback, or delete it. Only after P0–P3.

Ordered detail: `docs/03-implementation/03-TO-DO.md`.

## Key principle

No Apple Developer account. No $99/year. The MusicKit developer token is public and scraped
from Apple's own web bundle; the hidden WebView2 borrows the CDM that is already installed
on Windows and the subscription the user already pays for. Personal hobby project.
